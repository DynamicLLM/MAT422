# MAT 422 Student Project Requirements

## Project objective

Use Codex or another approved LLM-based coding agent as an AI modeling agent. The student defines a discipline-specific problem, objectives, available information, conditions, and constraints. The agent proposes appropriate models or methods, generates the implementation, evaluates results, and iterates toward a better solution.

## Required workflow

1. **Problem formulation** — state the problem, objective, inputs/data, assumptions, constraints, and success criteria.
2. **Model selection** — ask Codex to propose reasonable candidate models/methods and justify the final choice.
3. **Software implementation** — implement the selected method in Python, MATLAB, R, SAS, or Stata.
4. **Execution and verification** — run the software yourself when necessary; do not claim success without evidence.
5. **Validation** — evaluate the result against quantitative criteria and model assumptions.
6. **Comparison or optimization** — compare alternatives and/or improve parameters, features, or the model.
7. **AI critique** — document important Codex errors, corrections, limitations, or cases where human judgment was required.
8. **Final communication** — explain the method, results, validation, limitations, and conclusions.

## Interface requirement

A formal API is not required. A reproducible machine-actionable workflow is required. Depending on the platform, this can use scripts, notebooks, command execution, APIs, packages, or structured file/data exchange.

## Minimum project evidence

- Clear problem statement and constraints
- Data/input description
- Candidate models/methods considered
- Reproducible code or notebook
- Evidence of Codex/AI contribution
- Validation results
- At least one comparison or meaningful improvement iteration when applicable
- Final results and limitations
- GitHub repository with organized files

## GitHub rules

- Do not commit passwords, API keys, private datasets, or other secrets.
- Use relative paths so the project is reproducible on another machine when practical.
- Include a README with setup and run instructions.
- Use meaningful commit messages.
- Keep generated outputs that are needed to understand the final result; avoid committing unnecessary temporary files.
